# پایگاه دادهٔ گموریا — قرارداد

این سند **قرارداد** است، نه راهنما. هر چیزی که در آن نوشته شده با آزمون اجراشده پشتیبانی می‌شود، و هر چیزی که پشتیبانی نمی‌شود در بخش «محدودیت‌ها» آمده است.

---

## ۱. قاعدهٔ بنیادی

> **یک اسکیمای واحد، یک دیالکت واحد، یک مجموعه مایگریشن واحد — برای PGlite و PostgreSQL، بدون استثنا.**

PGlite همان PostgreSQL است که به WebAssembly کامپایل شده و درون پروسه اجرا می‌شود. به همین دلیل SQL تولیدشده برای یکی، عیناً روی دیگری اجرا می‌شود. اما این «شبیه» بودن کافی نیست: اگر دو مسیر از هم فاصله بگیرند، باگ فقط در تولید پیدا می‌شود. پس:

* اسکیما فقط در `src/db/schema/` تعریف می‌شود (Drizzle، دیالکت `pg-core`)؛
* مایگریشن‌ها فقط با `npm run db:generate` تولید می‌شوند — فایل SQL دست‌نویس اضافه نمی‌شود؛
* همان فایل‌های `.sql` در `src/db/migrations/` توسط هر دو موتور اجرا می‌شوند؛
* تست دوسویه (`npm run test:postgres`) همان مجموعهٔ آزمون را روی PGlite و روی PostgreSQL واقعی اجرا می‌کند.

| | توسعه / پیش‌نمایش | تولید |
|---|---|---|
| موتور | PGlite 0.5 (WASM، درون‌پروسه) | PostgreSQL واقعی (نسخهٔ ۱۸٫۶ آزموده شده) |
| اتصال | فایل در `.data/pglite` | `DATABASE_URL` |
| درایور Drizzle | `drizzle-orm/pglite` | `drizzle-orm/node-postgres` |
| مایگریشن خودکار | بله (پیش‌فرض) | **ممنوع** — گام صریح انتشار |
| چند اتصال همزمان | یک اتصال | مخزن اتصال `pg` |

## ۲. تصمیم D-05 — خوشهٔ تولید باید UTF-8 باشد

این مهم‌ترین یافتهٔ فاز ۰ است و به‌تنهایی می‌توانست ماه‌ها بعد به‌صورت «جست‌وجوی فارسی کار نمی‌کند» برگردد.

PostgreSQL اگر با تنظیمات پیش‌فرض `initdb` ساخته شود، روی بسیاری از سیستم‌ها با `SQL_ASCII` و `ctype = C` بالا می‌آید. در چنین خوشه‌ای متن فارسی **بی‌صدا دور ریخته می‌شود**:

| خوشه | `to_tsvector('simple','زمرد موزو کلمبیا')` | جست‌وجو |
|---|---|---|
| پیش‌فرض (`SQL_ASCII` / `C`) | `''` (رشتهٔ خالی) | ❌ پیدا نمی‌شود |
| `--encoding=UTF8 --locale=C.UTF-8` | `'زمرد':1 'موزو':2 'کلمبیا':3` | ✅ |

PGlite همیشه UTF-8 است، بنابراین **آزمون‌های توسعه این خرابی را نشان نمی‌دهند**. به همین دلیل:

1. `src/db/capabilities.ts` قابلیت واقعی را روی اتصال باز **می‌سنجد** (`pg_database.encoding` + یک `to_tsvector` واقعی روی متن فارسی)؛
2. `/api/health` این نتیجه را برمی‌گرداند و در صورت پشتیبانی‌نشدن، وضعیت را `degraded` اعلام می‌کند — یعنی موزه سالم به نظر نمی‌رسد در حالی که جست‌وجو مرده است؛
3. `npm run db:doctor` روی آن **خطا می‌دهد** (خروج غیرصفر)؛
4. هر دو مجموعهٔ آزمون پایگاه داده این شرط را assert می‌کنند؛
5. `scripts/dev-postgres.mts` و `scripts/with-postgres.mts` خوشهٔ محلی را با `--encoding=UTF8 --locale=C.UTF-8` می‌سازند.

**الزام استقرار:** خوشهٔ تولید باید با `initdb --encoding=UTF8 --locale=C.UTF-8` (یا معادلش در سرویس مدیریت‌شده) ساخته شود. سرویس‌های مدیریت‌شده معمولاً UTF8 هستند، اما این باید **پیش از انتشار** با `npm run db:doctor` تأیید شود، نه فرض شود.

## ۳. متغیرهای محیطی

فایل کامل و مستند: [`.env.example`](../.env.example). هیچ متغیر محرمانه‌ای در مخزن نیست (`.env` و `.env.*` در `.gitignore` هستند؛ فقط `.env.example` کامیت می‌شود).

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `DATABASE_URL` | — | رشتهٔ اتصال PostgreSQL. در تولید **الزامی**؛ حضورش یعنی درایور `postgres`. |
| `DB_DRIVER` | خودکار | فقط برای اجبار صریح `pglite` یا `postgres`. در تولید مقدار `pglite` رد می‌شود. |
| `DATABASE_SSL` | `false` | برای سرویس‌های مدیریت‌شده با TLS. |
| `PGLITE_DATA_DIR` | `.data/pglite` | مسیر دادهٔ توسعه. هرگز کامیت نمی‌شود. |
| `DB_AUTO_MIGRATE` | `true` در توسعه، `false` در تولید | در تولید مقدار `true` رد می‌شود. |

### قواعدی که در کد اعمال می‌شوند (نه در مستندات)

| وضعیت | نتیجه |
|---|---|
| `NODE_ENV=production` بدون `DATABASE_URL` | **امتناع از اجرا** — پیام صریح، بدون بازگشت به PGlite |
| `NODE_ENV=production` با `DB_DRIVER=pglite` | **امتناع از اجرا** |
| `NODE_ENV=production` با `DB_AUTO_MIGRATE=true` | **امتناع از اجرا** |
| `DB_DRIVER=postgres` بدون URL | خطا |
| `DATABASE_URL` با طرحی غیر از `postgres://` | خطا |

این قواعد در سه لایه اعمال می‌شوند: زودپ (zod) در `src/lib/env.ts`، پیش‌پرواز `scripts/preflight.mts`، و یک assert نهایی درست پیش از ساخت اتصال. اجرای واقعی:

```console
$ npm start            # بدون DATABASE_URL
GEMORIA cannot start because the environment configuration is invalid:
  • DATABASE_URL is required in production. GEMORIA will not fall back to PGlite: …
✗ Refusing to start. Fix the configuration above and run again.
$ echo $?
1
```

## ۴. راه‌اندازی در توسعه

```bash
npm install
npm run dev          # PGlite در .data/pglite ساخته و مایگریشن می‌شود
```

هیچ راه‌اندازی دستی لازم نیست: بار اول، دایرکتوری داده ساخته می‌شود، همهٔ مایگریشن‌ها اعمال می‌شوند و موزه با دادهٔ خالی بالا می‌آید. `curl localhost:3000/api/health` وضعیت را نشان می‌دهد.

**آزمودن با PostgreSQL واقعی** (همان مسیری که تولید می‌رود، بدون نصب چیزی):

```bash
npm run db:server                                  # پنجرهٔ ۱: PostgreSQL 18 با UTF-8
DATABASE_URL="postgres://gemoria:gemoria_local_dev_only@127.0.0.1:54329/gemoria" npm run db:migrate
DATABASE_URL="…" npm run db:doctor
DATABASE_URL="…" npm start                         # حالت تولید، با PostgreSQL واقعی
```

`npm run db:server` از `embedded-postgres` استفاده می‌کند: باینری‌های واقعی PostgreSQL که به‌عنوان بستهٔ npm می‌آیند. نه Docker لازم است، نه `psql`، نه دسترسی روت. داده در `.pgdata/` می‌ماند (git-ignored).

## ۵. مایگریشن‌ها

```
src/db/schema/{enums,types,identity,media,specimens,platform,index}.ts   ← منبع حقیقت
src/db/migrations/0000_tidy_puppet_master.sql                          ← SQL تولیدشده، قابل بازبینی
src/db/migrations/meta/{_journal.json,0000_snapshot.json}              ← دفتر Drizzle Kit
```

| نقش | فرمان |
|---|---|
| تغییر اسکیما | فایل‌های `src/db/schema/` را ویرایش کنید |
| تولید SQL | `npm run db:generate` |
| بازبینی | فایل `.sql` تولیدشده را بخوانید (این گام حذف‌شدنی نیست) |
| اعمال | `npm run db:migrate` (روی موتور فعال، هر کدام که باشد) |
| بازرسی | `npm run db:doctor` |

Drizzle تاریخچهٔ اعمال را در جدول `drizzle.__drizzle_migrations` **داخل همان پایگاه داده** نگه می‌دارد؛ بنابراین مایگریشن هرگز دو بار اعمال نمی‌شود (آزمون‌شده در هر دو موتور).

در تولید: `npm run db:migrate` **قبل از** اجرای سرور، به‌عنوان گام جداگانه و بازبینی‌شدهٔ انتشار. سرور وب خودش مایگریشن نمی‌کند.

## ۶. اسکیمای فاز ۰

هشت جدول، همه با کلید UUID تولیدشده در پایگاه داده، همه با `timestamptz`:

| جدول | نقش |
|---|---|
| `users`, `sessions`, `audit_log` | هویت و حسابرسی پنل مدیریت (بدون احراز هویت در فاز ۰) |
| `media_assets`, `media_translations` | دارایی‌های تصویری و فراداده‌های چندزبانه |
| `specimens`, `specimen_translations` | نمونهٔ سنگ‌ها؛ محتوای متنی در جدول ترجمه |
| `app_settings` | تنظیمات زمان اجرا |

نکات طراحی:

* **متن از ساختار جدا است.** `specimens` فقط داده‌های مشترک را دارد (ابعاد، وزن، سختی، عکس)؛ نام، توضیح و داستان در `specimen_translations` با `locale` می‌آیند. افزودن انگلیسی و عربی یعنی افزودن سطر، نه تغییر اسکیما.
* **جست‌وجوی فارسی در پایگاه داده.** `search_tsv` یک ستون `tsvector` تولیدشده (STORED) با ایندکس GIN است. PGlite افزونهٔ `pg_trgm` ندارد، بنابراین جست‌وجوی مبهم با ایندکس سه‌گرام ممکن نیست؛ `tsvector` + GIN انتخاب شد چون در هر دو موتور یکسان کار می‌کند.
* **یکتا بودن نامک در هر زبان.** `(locale, slug)` یکتاست، ولی همان نامک در انگلیسی می‌تواند تکرار شود — نه در فارسی.
* **حذف آبشاری** از نمونه به ترجمه‌هایش.

اثبات: `tests/helpers/database-suite.ts` — ۱۶ assertion مستقل از موتور، شامل شمارش مایگریشن‌ها، اجرای دوبارهٔ بی‌اثر، فهرست دقیق هشت جدول، رد شدن نقش نامعتبر، قالب UUID، دقت `weight_ct` (`'24.137'`)، تطبیق و عدم تطبیق جست‌وجوی فارسی، وجود ایندکس GIN، یکتایی نامک در هر زبان، حذف آبشاری، نقض کلید خارجی، `timestamptz`، رفت‌وبرگشت JSONB فارسی، و پشتیبانی از توکن‌سازی فارسی.

## ۷. پشتیبان‌گیری و بازیابی

* **تولید (PostgreSQL):** `pg_dump --format=custom` طبق برنامهٔ سرویس میزبان. این در فاز ۰ پیکربندی نشده است چون میزبان انتخاب نشده (D-02).
* **توسعه (PGlite):** `.data/pglite` یک دایرکتوری است؛ کپی آن در حالی که سرور خاموش است، معادل پشتیبان است. این هرگز کامیت نمی‌شود.

## ۸. محدودیت‌های شناخته‌شده

* **PGlite تک‌اتصال است.** سرور توسعهٔ Next در حالت چند worker می‌تواند به همان فایل دست بزند؛ برای همین اتصال روی `globalThis` memoize شده است. در تولید این محدودیت وجود ندارد.
* **بدون `pg_trgm`، `unaccent`، `citext`.** نرمال‌سازی متن (حذف اعراب، یکسان‌سازی ی/ک عربی) در لایهٔ برنامه انجام می‌شود، نه با افزونه.
* **بدون استخر اتصال در توسعه.** `pg.Pool` فقط در مسیر `postgres` ساخته می‌شود.
* **مایگریشن‌ها هنوز هیچ دادهٔ نمونه‌ای ندارند.** نمونه‌های ۱۲ تا ۲۰ گانه (D-04) در فازی بعد، از مسیر واقعی آپلود/انتشار، اضافه می‌شوند.
